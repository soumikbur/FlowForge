Multi-Tier Component Architecture

FlowForge enforces strict layer boundaries across Presentation, Ingress, Application, and Persistence tiers:

+-----------------------------------------------------------------------------------+ | CLIENT BROWSER | +-----------------------------------------------------------------------------------+ | HTTP / WS v +-----------------------------------------------------------------------------------+ | apps/web (Port 3000) - Next.js 14 App Router, React Flow Canvas, Dual Theme HUD | +-----------------------------------------------------------------------------------+ | REST API / Auth v +-----------------------------------------------------------------------------------+ | apps/api (Port 4000) - Express.js REST API, Rate Limiting, RBAC, Webhooks Engine | +-----------------------------------------------------------------------------------+ | | Queue Jobs v v State & Audits +---------------------------+ +---------------------------------+ | Redis 7 (Port 6379) | | PostgreSQL 16 (Port 5432) | | BullMQ Queues & Locks | | Prisma ORM, Partitioned Tables | +---------------------------+ +---------------------------------+ ^ ^ | Pull Steps | Read / Write +-----------------------------------------------------------------------------------+ | apps/worker (Port 4001) - BullMQ Task Executor, Step Runners, Sandbox Engine | +-----------------------------------------------------------------------------------+

REST API Endpoints Summary

All endpoints are served from the API Gateway on port 4000 with standard JWT / API Key authorization:

GET /health - Microservice readiness & health checks POST /api/v1/auth/login - Authenticate tenant user session GET /api/v1/workflows - List workflows with pagination & tags POST /api/v1/workflows - Create new workflow specification GET /api/v1/workflows/:id - Retrieve workflow detail & published version PUT /api/v1/workflows/:id - Update draft definition (nodes & edges) POST /api/v1/workflows/:id/publish - Publish workflow draft version POST /api/v1/workflows/:id/execute - Trigger synchronous or asynchronous run GET /api/v1/executions/:id - Poll execution state machine & step logs GET /api/v1/approvals - Query pending human approval requests POST /api/v1/approvals/:id/decide - Approve or reject approval step GET /api/v1/templates - Browse curated automation templates catalog POST /api/v1/portability/export - Export workflow definition to JSON bundle POST /api/v1/portability/import - Import and validate workflow JSON bundle

Production Deployment Options

FlowForge can be deployed via Docker Compose or 1-click cloud platforms using the included configurations:

Option 1: Production Docker Compose

git clone https://github.com/soumikbur/FlowForge.git cd FlowForge cp .env.example .env.production # Edit .env.production with your strong secrets docker compose -f docker-compose.prod.yml up -d

Option 2: Public GitHub Container Registry (GHCR)

Pull pre-built production container images directly from GitHub:

docker pull ghcr.io/soumikbur/flowforge-api:latest docker pull ghcr.io/soumikbur/flowforge-worker:latest docker pull ghcr.io/soumikbur/flowforge-web:latest

Option 3: 1-Click Cloud Deployment (Render Blueprint)

Deploy all 5 services (PostgreSQL, Redis, API, Worker, Web) automatically using render.yaml:

1. Open https://dashboard.render.com/blueprints 2. Connect repository: https://github.com/soumikbur/FlowForge 3. Click "Apply Blueprint" to provision full infrastructure
