# Enterprise Data Governance, Semantic Analytics, and Business Intelligence

## 1. Executive Summary

This document describes the enterprise data governance, semantic analytics, and business intelligence architecture implemented for FlowForge. The platform transforms raw workflow execution data, operational events, connector calls, and policy governance decisions into actionable, verifiable business intelligence while upholding strict data quality, referential integrity, and multi-tenant isolation.

---

## 2. Architectural Overview & Canonical Data Model

FlowForge establishes a dimensional star-schema semantic data model derived from operational runtime events without requiring fragile ETL duplications:

```
                  +-----------------------------------+
                  |         Workflow Dimension        |
                  | id, name, version, status, tags   |
                  +-----------------+-----------------+
                                    | 1
                                    |
                                    | N
                  +-----------------v-----------------+
                  |          Execution Facts          |
                  | id, workflowId, triggerType,      |
                  | status, durationMs, errorDetails  |
                  +--------+-----------------+--------+
                           | 1               | 1
                           |                 |
                         N |               N |
  +------------------------v----+       +----v------------------------+
  |     Node Execution Facts    |       |   Governance Activity Facts  |
  | stepId, nodeId, durationMs, |       | policyId, ruleId, decision, |
  | inputBytes, outputBytes,    |       | violationSeverity, waitTime |
  | errorCategory, retries      |       +-----------------------------+
  +--------------+--------------+
                 | N
                 |
                 | 1
  +--------------v--------------+
  |  Integration Activity Facts |
  | connectorId, provider,      |
  | latencyMs, p95, status, 429 |
  +-----------------------------+
```

### Key Dimensions and Fact Tables

1. **Workflow Dimensions**: `workflowId`, `name`, `version`, `status`, `organizationId`, `workspaceId`, `environment`.
2. **Execution Facts**: `executionId`, `workflowId`, `status`, `startedAt`, `completedAt`, `durationMs`, `triggerType`, `retryCount`, `errorDetails`.
3. **Node Execution Facts**: `stepId`, `executionId`, `nodeId`, `nodeType`, `status`, `startedAt`, `completedAt`, `durationMs`, `errorMessage`.
4. **Integration Activity Facts**: `connectionId`, `provider`, `connectorName`, `totalCalls`, `successCount`, `errorRatePercentage`, `averageLatencyMs`, `p95LatencyMs`, `rateLimitHits`.
5. **Governance Activity Facts**: `policyId`, `policyVersion`, `ruleId`, `severity`, `enforcementAction`, `approvalWaitTimeMs`.

## 3. Automation ROI & Value Realization Framework

### 3.1 Transparent Financial Model

Organizations need to measure the concrete financial and operational returns generated by automation. FlowForge computes ROI using transparent, verifiable formulas:

$$\text{Estimated Hours Saved} = \frac{\text{Successful Executions} \times \text{Manual Minutes Per Run}}{60}$$

$$\text{Estimated Labor Cost Avoided} = \text{Estimated Hours Saved} \times \text{Blended Hourly Wage}$$

$$\text{Net Automation Savings} = \text{Labor Cost Avoided} - \text{Allocated Platform License Cost} - \text{Infrastructure Consumption Cost}$$

### 3.2 Assumption Versioning & Governance

- Default assumptions: 15 minutes manual handling per run, $45.00/hour wage, $0.00 license, $0.00 infrastructure.
- Organizations can configure organization-wide or workflow-specific overrides via `POST /api/v1/analytics/roi/assumptions`.
- Query parameters (`manualMinutes`, `hourlyWage`) allow interactive simulation without persisting changes.
- All ROI calculations report whether custom or default assumptions were applied.

## 4. Data Quality Assurance & Health Diagnostics

To prevent corrupted telemetry from misleading executive reporting, FlowForge includes an active **Data Quality Auditor** accessible via `GET /api/v1/analytics/data-quality`.

### Verification Rules

| Check Name               | Target Entities   | Failure Conditions                                                  | Severity      |
| :----------------------- | :---------------- | :------------------------------------------------------------------ | :------------ |
| `SCHEMA_INTEGRITY`       | Executions, Steps | Missing ID, workflow reference, or status                           | HIGH          |
| `TIMESTAMP_VALIDITY`     | Executions, Steps | Negative duration (`completedAt < startedAt`), future creation date | HIGH / MEDIUM |
| `RELATIONAL_INTEGRITY`   | Steps, Approvals  | Orphaned records referencing non-existent execution IDs             | HIGH          |
| `FAILURE_CLASSIFICATION` | Executions        | `FAILED` status with no diagnostic error message or category        | MEDIUM        |
| `STREAM_INTEGRITY`       | Stream Events     | Missing CloudEvents headers, event type, or source                  | MEDIUM        |

### Overall Health Score

The platform computes a normalized 0–100% score across all audit checks:

- **PASS**: Score $\ge 90\%$
- **WARN**: Score between $70\%$ and $89\%$
- **FAIL**: Score $< 70\%$

## 5. API Platform Endpoints

Mounted under `/api/v1/analytics`:

- `GET /roi`: Computes automation ROI, hours avoided, labor savings, and per-workflow breakdowns.
- `GET /roi/assumptions`: Retrieves active ROI parameters for organization or specific workflow.
- `POST /roi/assumptions`: Updates organization ROI benchmark assumptions (requires `analytics:write`).
- `GET /data-quality`: Performs real-time schema and temporal integrity audit.
- `GET /governance`: Aggregates policy violations by severity, approval wait times, and enforcement actions.
- `GET /integrations`: Computes connector call volume, error rates, average and P95 latencies, and 429 spikes.
- `GET /reports`: Lists saved report definitions (requires `reports:read`).
- `POST /reports`: Creates a saved report specification (requires `reports:write`).
- `GET /reports/:id`: Retrieves saved report configuration (requires `reports:read`).
- `DELETE /reports/:id`: Deletes saved report configuration (requires `reports:write`).
- `GET /reports/:id/export`: Executes saved report and downloads formatted file (`format=CSV` or `format=JSON`).

## 6. Web UI Dashboard

The FlowForge web interface includes a comprehensive analytics console under `/analytics`:

1. **Executive Overview**: High-level KPI cards for Net Automation Value, Hours Avoided, Execution Success Rate, and Data Quality Score.
2. **Business ROI & Value Tab**: Interactive sliders/inputs for manual processing time and wage rates with real-time recalculation, plus workflow value breakdown table.
3. **Operational Performance Tab**: Duration percentiles (P50, P95, P99), trigger distributions, and self-healing retry metrics.
4. **Integration Reliability Tab**: SaaS connector table tracking error rates, average and P95 latencies, and 429 rate limit counts.
5. **Governance & Compliance Tab**: Policy enforcement counts, violation severity distributions, and human approval bottlenecks.
6. **Data Quality Health Tab**: Verification check statuses, individual test scores, and corrupt record diagnostics.
7. **Saved Reports Tab**: One-click download of CSV and JSON exports for executive reporting.
